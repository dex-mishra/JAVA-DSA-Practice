=== day: 4
micro_title: Prefix sums and Kadane — subarrays without re-adding
micro_theory: ps-prefix-sum-basics, ps-prefix-sum-hashmap, sw-monotonicity-requirement, kad-kadane, kad-min-so-far, cpp-integer-overflow
--- micro | Micro-theory (10 minutes) | mixed
Day 1's running sum comes back with two superpowers.

✍️ **Prefix sums.** Store every running total in `pre` (with a leading 0). Any range sum is `pre[r+1] − pre[l]` in O(1). Draw the boundary picture once ([[ps-prefix-sum-basics#index-convention]]).
✍️ **Prefix sum + hash map.** "Subarray sum = k" means "two prefixes differ by k" — that is Two Sum on prefix sums. Seed the map with `{0: 1}` ([[ps-prefix-sum-hashmap#seed]]).
✍️ **Why not a sliding window?** Negative numbers make window sums non-monotone ([[sw-monotonicity-requirement#counterexample]]).
✍️ **Kadane.** Best subarray *ending here* = max(x, best ending at the previous index + x) ([[kad-kadane#idea]]). And its cousin: for "buy then sell", the best buy day is the minimum so far ([[kad-min-so-far#idea]]).
- Sums get big → `long long` ([[cpp-integer-overflow#where]]).
--- card | Pattern card | write
✍️ PREFIX SUM — `pre[0]=0; pre[i+1]=pre[i]+a[i]`; sum(l..r) = pre[r+1] − pre[l].
✍️ PREFIX + MAP — trigger "count subarrays with sum k" (negatives ok). cnt{0:1}; ans += cnt[run−k]; cnt[run]++.
✍️ KADANE — cur = max(x, cur+x); best = max(best, cur); init with a[0].
✍️ MIN SO FAR — profit = x − minSoFar; then minSoFar = min(minSoFar, x).

=== problem: range-sum-query-immutable
theory_refs:
- brainstorm | Overlapping queries re-add the same elements | ps-prefix-sum-basics#think | Why per-query loops waste work.
- pseudocode | `pre` of size n+1 with pre[0] = 0 | ps-prefix-sum-basics#index-convention | The boundary picture that kills off-by-ones.
- solution | `long long` storage | cpp-integer-overflow#where | Prefix sums overflow first.
- carry | Static only | ps-prefix-sum-basics#pitfalls | Updates need a different structure.
stuck_refs:

--- understand | Understand | mixed
✍️ Design a class: constructor gets an array; `sumRange(l, r)` returns a[l] + … + a[r] (inclusive). Up to 10⁴ queries on n ≤ 10⁴.
- The array never changes ("immutable").
--- analyse | Analyse | write
✍️ Per-query loop: 10⁴ queries × 10⁴ length = 10⁸ — borderline. The real point: many queries on a static array.
✍️ By hand: sum(2..4) = (sum of first 5) − (sum of first 2). If I had all "sum of first i", every query is one subtraction.
✍️ Edges: l = 0 (must not read index −1); l == r.
--- brainstorm | Brainstorm: brute → optimal | write
✍️ **1. Brute.** Loop from l to r per query. O(n) per query.
✍️ ↳ Bottleneck: different queries re-add overlapping elements.
✍️ ↳ Unlock: "recomputing something…" → precompute every running total once.
✍️ **2. Optimal.** Build `pre` in O(n); answer each query as `pre[r+1] − pre[l]` in O(1).
--- algorithm | Algorithm in words | write
✍️ 1. In the constructor, build pre of size n+1 with pre[0] = 0 and pre[i+1] = pre[i] + a[i].
✍️ 2. For a query (l, r), return pre[r+1] − pre[l].
--- pseudocode | Pseudocode | write
```
CONSTRUCT  pre = [0] * (n+1)
           for i in 0..n-1: pre[i+1] = pre[i] + a[i]
QUERY      return pre[r+1] - pre[l]
```
--- solution | Reference C++ | screenshot
```cpp
class NumArray {
    vector<long long> pre;
public:
    NumArray(vector<int>& a) : pre(a.size() + 1, 0) {
        for (int i = 0; i < (int)a.size(); i++) pre[i + 1] = pre[i] + a[i];
    }
    int sumRange(int l, int r) { return (int)(pre[r + 1] - pre[l]); }
};
```
--- dry_run | Dry run | screenshot
a = [−2, 0, 3, −5, 2, −1] → pre = [0, −2, −2, 1, −4, −2, −3]
| query | formula | value |
|---|---|---|
| (0, 2) | pre[3] − pre[0] | 1 |
| (2, 5) | pre[6] − pre[2] | −1 |
| (0, 5) | pre[6] − pre[0] | −3 |
--- edges | Edge cases and complexity | mixed
✍️ Build O(n), query O(1), space O(n).
✍️ The leading 0 means l = 0 needs no special case.
--- carry | Carry forward | write
✍️ Many range-sum queries on a static array → prefix sums.
✍️ `pre[k]` = sum of the first k elements = boundary before index k.
✍️ Sum of a[l..r] = pre[r+1] − pre[l]. Memorise the picture, not the formula.

+++ sibling: 238 | product-of-array-except-self | Product of Array Except Self | Medium | must
maps: Prefix and suffix **products** instead of sums; division is banned, so combine a left pass and a right pass.
--- analyse | Analyse | write
✍️ out[i] = product of all elements except a[i]; O(n), no division.
✍️ Division would break on zeros anyway.
--- brainstorm | Brainstorm | write
✍️ Brute: for each i multiply the rest → O(n²). out[i] = (product of a[0..i−1]) × (product of a[i+1..n−1]) → a forward pass and a backward pass. Write the forward pass into out, then sweep backwards with one variable → O(1) extra.
--- algorithm | Algorithm in words | write
✍️ Pass 1: out[i] = product of everything left of i. Pass 2 from the right: multiply out[i] by a running product of everything right of i.
--- pseudocode | Pseudocode | write
```
out[0] = 1
for i in 1..n-1: out[i] = out[i-1] * a[i-1]
right = 1
for i from n-1 down to 0: out[i] *= right; right *= a[i]
```
--- solution | Reference C++ | screenshot
```cpp
class Solution {
public:
    vector<int> productExceptSelf(vector<int>& a) {
        int n = a.size();
        vector<int> out(n, 1);
        for (int i = 1; i < n; i++) out[i] = out[i - 1] * a[i - 1];
        int right = 1;
        for (int i = n - 1; i >= 0; i--) { out[i] *= right; right *= a[i]; }
        return out;
    }
};
```
--- quick_theory | Quick theory | mixed
✍️ "Everything except me" = left part ⊕ right part ([[ps-prefix-suffix-passes#idea]]); zeros need no special case ([[ps-prefix-suffix-passes#why-no-division]]).
--- tests | Tests | hidden

+++ sibling: 304 | range-sum-query-2d-immutable | Range Sum Query 2D - Immutable | Medium | optional
maps: The same idea in two dimensions with inclusion–exclusion.
--- analyse | Analyse | write
✍️ Many queries for the sum of a sub-rectangle of a static matrix.
--- brainstorm | Brainstorm | write
✍️ Per-query double loop → O(R·C) per query. 2D prefix P[r+1][c+1] = sum of rectangle (0,0)..(r,c) → O(1) per query.
--- algorithm | Algorithm in words | write
✍️ Build P with "add up, add left, subtract the overlap"; answer with four lookups.
--- pseudocode | Pseudocode | write
```
P[r+1][c+1] = g[r][c] + P[r][c+1] + P[r+1][c] - P[r][c]
sum = P[r2+1][c2+1] - P[r1][c2+1] - P[r2+1][c1] + P[r1][c1]
```
--- solution | Reference C++ | screenshot
```cpp
class NumMatrix {
    vector<vector<long long>> P;
public:
    NumMatrix(vector<vector<int>>& g) {
        int R = g.size(), C = g[0].size();
        P.assign(R + 1, vector<long long>(C + 1, 0));
        for (int r = 0; r < R; r++)
            for (int c = 0; c < C; c++)
                P[r + 1][c + 1] = g[r][c] + P[r][c + 1] + P[r + 1][c] - P[r][c];
    }
    int sumRegion(int r1, int c1, int r2, int c2) {
        return (int)(P[r2 + 1][c2 + 1] - P[r1][c2 + 1] - P[r2 + 1][c1] + P[r1][c1]);
    }
};
```
--- quick_theory | Quick theory | mixed
✍️ Inclusion–exclusion in both the build and the query ([[ps-2d-prefix-sum#query]]).

=== problem: subarray-sum-equals-k
theory_refs:
- analyse | Negatives present | sw-monotonicity-requirement#counterexample | Why a window cannot work here.
- brainstorm | "Search earlier prefixes for run − k" | ps-prefix-sum-hashmap#think | The bottleneck that becomes a lookup.
- brainstorm | Same idea as Two Sum | hash-complement-lookup#idea | Complement lookup on prefix sums.
- pseudocode | `cnt[0] = 1` | ps-prefix-sum-hashmap#seed | Subarrays starting at index 0.
- pseudocode | Query, then record | ps-prefix-sum-hashmap#pitfalls | Avoid counting empty subarrays when k = 0.
stuck_refs:
- 10 | sw-monotonicity-requirement#rule
- 20 | ps-prefix-sum-basics#idea
- 30 | ps-prefix-sum-hashmap#idea
- 40 | ps-prefix-sum-hashmap#seed
--- understand | Understand | mixed
✍️ f(array of ints, possibly negative; k) → number of contiguous subarrays whose sum is exactly k.
- n ≤ 2·10⁴, values in [−1000, 1000], k in [−10⁷, 10⁷].
- [1, 1, 1], k = 2 → 2. [1, 2, 3], k = 3 → 2 ([1,2] and [3]).
--- analyse | Analyse | write
✍️ "Subarray sum" + negatives → not a window. "Count" + "exactly k" → think prefix sums.
✍️ By hand: sum(i..j) = pre[j+1] − pre[i]. For a fixed end, I want starts whose prefix equals (current prefix − k).
✍️ Hard part: counting **all** such starts quickly, and not missing subarrays that start at 0.
✍️ Edges: k = 0; negative values; a single element equal to k.
--- brainstorm | Brainstorm: brute → optimal | write
✍️ **1. Brute.** All (i, j) with an inner sum loop. O(n³).
✍️ **2. Better.** Fix i, extend j with a running sum. O(n²) — 4·10⁸, too slow in practice.
✍️ ↳ Bottleneck: for each end, trying every start.
✍️ ↳ Job description: "count earlier prefix sums equal to run − k". Unlock: searching for a known value → store prefix sums in a map with their counts.
✍️ **3. Optimal.** One pass; `cnt[prefix] = how many times seen`; add cnt[run − k] at each step. O(n) time, O(n) space.
--- algorithm | Algorithm in words | write
✍️ 1. Keep a running prefix sum, starting at 0, and a map of prefix counts containing {0: 1}.
✍️ 2. For each element, add it to the running sum.
✍️ 3. Add the number of earlier prefixes equal to (running − k) to the answer.
✍️ 4. Record the current running sum in the map.
--- pseudocode | Pseudocode | write
```
STATE   cnt = map {0: 1}; run = 0; ans = 0
LOOP    for x in a
UPDATE    run += x
CHECK     ans += cnt[run - k]        (query first, using find)
UPDATE    cnt[run] += 1              (record after)
RETURN  ans
```
--- solution | Reference C++ | screenshot
```cpp
class Solution {
public:
    int subarraySum(vector<int>& a, int k) {
        unordered_map<long long, int> cnt;
        cnt[0] = 1;
        long long run = 0;
        int ans = 0;
        for (int x : a) {
            run += x;
            auto it = cnt.find(run - k);
            if (it != cnt.end()) ans += it->second;
            cnt[run]++;
        }
        return ans;
    }
};
```
--- dry_run | Dry run | screenshot

| x | run | need = run−k | cnt[need] | ans | cnt after |
|---|---|---|---|---|---|
| start | 0 | | | 0 | {0:1} |
| 1 | 1 | −2 | 0 | 0 | {0:1, 1:1} |
| 2 | 3 | 0 | 1 | 1 | {0:1, 1:1, 3:1} |
| 3 | 6 | 3 | 1 | 2 | {…, 6:1} |
--- edges | Edge cases and complexity | mixed
✍️ O(n) average time, O(n) space.
✍️ Without the {0: 1} seed, [3] with k = 3 returns 0.
✍️ Recording before querying with k = 0 counts each position as a zero-length subarray.
--- carry | Carry forward | write
✍️ Subarray sum = k (or divisible by k, or balanced counts) → prefix sum + hash map.
✍️ It is Two Sum where the "values" are prefix sums: store what you have seen, look up run − k.
✍️ Negatives allowed → do not use a sliding window.
--- followups | Interview follow-ups | screenshot
- *Longest subarray with sum k.* Map prefix → first index, seed {0: −1} ([[ps-prefix-sum-hashmap#variations]]).
- *Sum divisible by k.* Key by `run mod k`, normalised ([[ps-modular-prefix]]).
- *All values positive?* Then a sliding window also works in O(1) space.

+++ sibling: 974 | subarray-sums-divisible-by-k | Subarray Sums Divisible by K | Medium | must
maps: Same counting map, but keyed by the prefix sum's remainder mod k.
--- analyse | Analyse | write
✍️ Count subarrays whose sum is divisible by k. Values can be negative.
--- brainstorm | Brainstorm | write
✍️ sum(i..j) divisible ⇔ pre[j+1] ≡ pre[i] (mod k). Count equal remainders with an array of size k seeded with count[0] = 1. Normalise negative remainders.
--- algorithm | Algorithm in words | write
✍️ For each element: update the running remainder; add how many earlier prefixes had the same remainder; record it.
--- pseudocode | Pseudocode | write
```
cnt[k] = 0; cnt[0] = 1; run = 0; ans = 0
for x in a:
    run = ((run + x) % k + k) % k
    ans += cnt[run]; cnt[run]++
```
--- solution | Reference C++ | screenshot
```cpp
class Solution {
public:
    int subarraysDivByK(vector<int>& a, int k) {
        vector<int> cnt(k, 0);
        cnt[0] = 1;
        int run = 0, ans = 0;
        for (int x : a) {
            run = ((run + x) % k + k) % k;
            ans += cnt[run]++;
        }
        return ans;
    }
};
```

--- analyse | Analyse | write

--- brainstorm | Brainstorm | write
✍️ Map 0 → −1. Then "equal counts" = "sum 0". Longest subarray with sum 0: two equal prefix sums; store the **first** index of each prefix value, seed {0: −1}.
--- algorithm | Algorithm in words | write

--- pseudocode | Pseudocode | write

```
first = {0: -1}; run = 0; best = 0

    else: first[run] = i
```
--- solution | Reference C++ | screenshot
```cpp
class Solution {
public:
    int findMaxLength(vector<int>& a) {
        unordered_map<int, int> first;
        first[0] = -1;
        int run = 0, best = 0;
        for (int i = 0; i < (int)a.size(); i++) {
            run += a[i] ? 1 : -1;
            auto it = first.find(run);
            if (it != first.end()) best = max(best, i - it->second);
            else first[run] = i;
        }
        return best;
    }
};
```

=== problem: maximum-subarray
theory_refs:
- brainstorm | For a fixed end, the best start comes from the previous end | kad-kadane#think | How Kadane falls out of the bottleneck method.
- pseudocode | cur = max(x, cur + x) | kad-kadane#template | Extend or restart.
- solution | Initialise with a[0], not 0 | kad-kadane#pitfalls | The all-negative bug.
- followups | Proof by induction | kad-kadane#proof | What to say when asked why it is correct.
- carry | It is a 1D DP | dp-1d-linear#idea | "Best ending at i" is a DP state you will see again on Day 25.
stuck_refs:
- 10 | cx-constraints-to-target#table
- 20 | kad-kadane#idea
- 30 | kad-kadane#template
- 40 | kad-kadane#pitfalls
--- understand | Understand | mixed
✍️ f(array, possibly negative) → the largest sum of a non-empty contiguous subarray.
- n ≤ 10⁵ → O(n) or O(n log n).
- [−2,1,−3,4,−1,2,1,−5,4] → 6 ([4,−1,2,1]).
--- analyse | Analyse | write
✍️ By hand: I keep adding while the total helps. When the running total becomes negative it can only drag down anything after it, so I start fresh.
✍️ Hard part: the all-negative case — the answer is the single largest element, not 0.
✍️ Edges: n = 1; all negative; zeros.
--- brainstorm | Brainstorm: brute → optimal | write
✍️ **1. Brute.** All (i, j), sum each. O(n³), or O(n²) with running sums.
✍️ ↳ Bottleneck: for each end j, trying every start i.
✍️ ↳ Observation: the best subarray ending at j is either [a[j]] alone or (best subarray ending at j−1) + a[j]. So "best ending at j" comes from "best ending at j−1" in O(1).
✍️ **2. Optimal (Kadane).** cur = max(a[j], cur + a[j]); best = max(best, cur). O(n), O(1).
✍️ (Prefix-sum view: answer = max over j of pre[j+1] − min prefix before it — the same as tomorrow's stock problem.)
--- algorithm | Algorithm in words | write
✍️ 1. Set cur and best to the first element.
✍️ 2. For each next element: cur becomes the larger of (the element alone) and (cur plus the element).
✍️ 3. Update best with cur.
✍️ 4. Return best.
--- pseudocode | Pseudocode | write
```
STATE   cur = a[0]; best = a[0]
LOOP    for i in 1..n-1
UPDATE    cur  = max(a[i], cur + a[i])     extend or restart
          best = max(best, cur)
RETURN  best
```
--- solution | Reference C++ | screenshot
```cpp
class Solution {
public:
    int maxSubArray(vector<int>& a) {
        int cur = a[0], best = a[0];
        for (int i = 1; i < (int)a.size(); i++) {
            cur = max(a[i], cur + a[i]);
            best = max(best, cur);
        }
        return best;
    }
};
```
--- dry_run | Dry run | screenshot
| a[i] | cur | best |

```cpp
class Solution {
public:
    int maxProduct(vector<int>& a) {
        int hi = a[0], lo = a[0], best = a[0];
        for (int i = 1; i < (int)a.size(); i++) {
            int x = a[i];
            if (x < 0) swap(hi, lo);

            lo = min(x, lo * x);
```

```cpp
class Solution {
public:
    int maxSubarraySumCircular(vector<int>& a) {
        int total = 0, curMax = 0, curMin = 0, best = a[0], worst = a[0];
        for (int x : a) {
            curMax = max(x, curMax + x); best = max(best, curMax);
            curMin = min(x, curMin + x); worst = min(worst, curMin);
            total += x;
        }
        if (best < 0) return best;
        return max(best, total - worst);
    }
};
```

theory_refs:
- brainstorm | For each sell day, the best buy is the minimum before it | kad-min-so-far#think | The running-minimum idea.
- pseudocode | Profit first, then fold today into the minimum | kad-min-so-far#pitfalls | The order of the two updates.
- carry | The stock family | dp-state-machine#family | Day 29 extends this to cooldowns, fees and k transactions.
- carry | Connection to Kadane | kad-kadane#variations | Kadane on daily differences gives the same answer.
stuck_refs:
- 10 | cx-constraints-to-target#table
- 20 | kad-min-so-far#idea
- 30 | kad-min-so-far#template
--- understand | Understand | mixed
✍️ f(prices by day) → max of prices[j] − prices[i] with i < j, or 0 if no profit is possible. One buy, one sell.
- n ≤ 10⁵ → O(n).
- [7,1,5,3,6,4] → 5 (buy 1, sell 6). [7,6,4,3,1] → 0.
--- analyse | Analyse | write
✍️ By hand: walking day by day, I remember the cheapest price so far. Each day I ask "if I sold today, what would I make?".
✍️ Hard part: the buy must come **before** the sell — so the max minus the min of the whole array is wrong.
✍️ Edges: prices only fall → 0; one day → 0.
--- brainstorm | Brainstorm: brute → optimal | write
✍️ **1. Brute.** All pairs i < j. O(n²).
✍️ ↳ Bottleneck: for each sell day j, scanning all earlier days for the minimum.
✍️ ↳ Unlock: "recomputing something that changed a little" — the minimum of days 0..j−1 is the minimum of days 0..j−2 plus one more day.
✍️ **2. Optimal.** Keep minSoFar; profit today = price − minSoFar. O(n), O(1).
--- algorithm | Algorithm in words | write
✍️ 1. Remember the first price as the cheapest so far; best profit 0.
✍️ 2. For each later day: compute today's price minus the cheapest so far; update the best profit.
✍️ 3. Then update the cheapest so far with today's price.
--- pseudocode | Pseudocode | write
```
STATE   minSoFar = p[0]; best = 0
LOOP    for j in 1..n-1
UPDATE    best = max(best, p[j] - minSoFar)     sell today
          minSoFar = min(minSoFar, p[j])        today becomes a buy option
RETURN  best
```
--- solution | Reference C++ | screenshot
```cpp
class Solution {
public:
    int maxProfit(vector<int>& p) {
        int minSoFar = p[0], best = 0;
        for (int j = 1; j < (int)p.size(); j++) {
            best = max(best, p[j] - minSoFar);
            minSoFar = min(minSoFar, p[j]);
        }
        return best;
    }
};
```

=== cs_core: oop-04-polymorphism
subject: OOP
title: Polymorphism — compile time and run time
--- concept | Concept | write
✍️ **Polymorphism** = one interface, many behaviours: the same call does different things depending on the type.
✍️ **Compile-time (static)**: function overloading (same name, different parameters) and operator overloading; templates. Resolved by the compiler.
✍️ **Run-time (dynamic)**: a base-class pointer/reference calls a `virtual` function, and the **derived** class's override runs. Resolved at run time through the **vtable** (a per-class table of function pointers; each object stores a hidden pointer to its class's vtable).
✍️ Without `virtual`, the base version runs even if the object is derived (static binding).
--- code | C++ example | screenshot
```cpp
class Shape {
public:
    virtual double area() const { return 0; }
    virtual ~Shape() = default;               // virtual destructor: deleting via Shape* is safe
};
class Circle : public Shape {
    double r;
public:
    Circle(double r) : r(r) {}
    double area() const override { return 3.14159 * r * r; }   // override checks the signature
};
Shape* s = new Circle(2);
s->area();      // Circle::area — dynamic dispatch
delete s;       // calls ~Circle then ~Shape because the destructor is virtual
// overloading (compile-time):
int add(int a, int b); double add(double a, double b);
```
--- interview | Interview questions | mixed
✍️ **Q: Overloading vs overriding?** Overloading: same name, different parameter lists, same scope, compile time. Overriding: derived class redefines a base `virtual` function with the same signature, run time.
✍️ **Q: Why must a base class destructor be virtual?** `delete basePtr` on a derived object would otherwise call only the base destructor → the derived part leaks (undefined behaviour).
✍️ **Q: What is a vtable / vptr?** Each class with virtual functions has a vtable of function pointers; each object has a hidden vptr pointing to its class's vtable; a virtual call looks up the function through it.
- **Q: What is object slicing?** Assigning a derived object to a base object **by value** copies only the base part; virtual calls then use the base version. Use pointers/references to keep polymorphism.
- **Q: Can you overload by return type only?** No.
