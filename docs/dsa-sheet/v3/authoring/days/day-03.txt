=== day: 3
micro_title: Two pointers — let sorted order tell you which way to move
micro_theory: tp-opposite-ends, tp-why-discarding-is-safe, tp-fix-one-k-sum, tp-skip-duplicates, cpp-sort-and-comparators
--- micro | Micro-theory (10 minutes) | mixed
Yesterday's Two Sum needed a hash map because the array was unsorted. When the array is **sorted**, the order itself tells you which direction improves the answer — and you need no extra memory.

✍️ Put `l` at the start and `r` at the end. Compare, then move exactly one pointer. Each move throws away a whole set of pairs that provably cannot work → O(n) ([[tp-opposite-ends#idea]]).
✍️ Learn the one-line proof, because interviewers ask for it: "if `a[l] + a[r] < target`, every pair using `l` is too small, so `l` is useless" ([[tp-why-discarding-is-safe#argument]]).
✍️ For three numbers: sort, fix the first, two-pointer the rest ([[tp-fix-one-k-sum#idea]]), and skip duplicates by comparing with the previous element ([[tp-skip-duplicates#idioms]]).
- Sorting: `sort(a.begin(), a.end())`, O(n log n) ([[cpp-sort-and-comparators#basics]]).
--- card | Pattern card | write
✍️ OPPOSITE ENDS — trigger: sorted + pair, or palindrome/symmetry, or "O(1) space". `while (l < r)`: too small → l++, too big → r--.
✍️ WHY SAFE — the pointer you move cannot be part of any better answer.
✍️ K-SUM — sort; for i: skip a[i]==a[i−1]; two pointers on i+1..n−1; after a hit move both and skip equal neighbours.

--- understand | Understand | mixed
✍️ f(sorted array a (1-indexed answer), target) → [i, j] with i < j and a[i] + a[j] = target. Exactly one answer. Must use O(1) extra space.
- n ≤ 3·10⁴.
- [2, 7, 11, 15], target 9 → [1, 2].
--- analyse | Analyse | write
✍️ Same question as Two Sum, but sorted and with a space limit — the space limit rules out yesterday's map.
✍️ By hand: 2 + 15 = 17 is too big. Is 15 useful with anything? Its smallest partner is 2, already too big → 15 is useless. Drop it.
✍️ Hard part: trusting that dropping an element can never lose the answer.
✍️ Edges: negative numbers; the answer is the two end elements; equal values.
--- brainstorm | Brainstorm: brute → optimal | write
✍️ **1. Brute.** All pairs. O(n²).
✍️ **2. Better.** For each i, binary search target − a[i] in a[i+1..]. O(n log n), O(1).
✍️ ↳ Bottleneck: each search restarts from scratch, but as a[i] grows its partner can only get smaller.
✍️ **3. Hash map.** O(n) time but O(n) space — breaks the requirement.
✍️ **4. Optimal.** l = 0, r = n−1. Sum too small → only a bigger left element can help → l++. Too big → r--. O(n), O(1).
--- algorithm | Algorithm in words | write
✍️ 1. Start with one pointer at each end.
✍️ 2. While they have not met, add the two values.
✍️ 3. Equal to target → return the 1-based indices.
✍️ 4. Smaller → move the left pointer right. Larger → move the right pointer left.
--- pseudocode | Pseudocode | write
```
STATE   l = 0; r = n-1
LOOP    while l < r
CHECK     s = a[l] + a[r]
          if s == target: return [l+1, r+1]
UPDATE    if s < target: l++   else: r--
RETURN  []
```
--- solution | Reference C++ | screenshot
```cpp
class Solution {
public:
    vector<int> twoSum(vector<int>& a, int target) {
        int l = 0, r = (int)a.size() - 1;
        while (l < r) {
            int s = a[l] + a[r];
            if (s == target) return {l + 1, r + 1};
            if (s < target) l++;
            else r--;
        }
        return {};
    }
};
```

|---|---|---|---|

| l | r | sum | move |

--- edges | Edge cases and complexity | mixed
✍️ O(n) time, O(1) space.
✍️ 1-based output — easy to forget.
- Sum of two values ≤ 1000 in magnitude here, so no overflow; use `long long` in variants.
--- carry | Carry forward | write
✍️ Unsorted + indices → hash map. Sorted (or sortable when indices don't matter) + O(1) space → two pointers.
✍️ Every pointer move must be justified by "the discarded element cannot be in a valid answer".
--- followups | Interview follow-ups | screenshot
- *Count all pairs with sum < target.* When a[l] + a[r] < target, all r − l pairs (l, l+1..r) qualify ([[tp-opposite-ends#variations]]).
- *Pair with the closest sum.* Track min |s − target| while moving the same way.
- *Why is binary search per element worse?* O(n log n) vs O(n); it ignores that the partner moves monotonically.

+++ sibling: 977 | squares-of-a-sorted-array | Squares of a Sorted Array | Easy | must
maps: The biggest square is always at one of the two ends — two pointers fill the output from the back.
--- analyse | Analyse | write
✍️ Sorted (may contain negatives); return the squares in sorted order in O(n).
✍️ Brute: square and sort → O(n log n).
--- brainstorm | Brainstorm | write
✍️ Bottleneck: sorting, although the squares are "large at both ends, small in the middle". The largest remaining square is at l or r → write it at the end of the output and move that pointer.
--- algorithm | Algorithm in words | write
✍️ l = 0, r = n−1, write = n−1; compare |a[l]| and |a[r]|; put the larger square at out[write], move that pointer, write--.
--- pseudocode | Pseudocode | write
```
l = 0; r = n-1
for w from n-1 down to 0:
    if |a[l]| > |a[r]|: out[w] = a[l]^2; l++
    else: out[w] = a[r]^2; r--
```
--- solution | Reference C++ | screenshot
```cpp
class Solution {
public:
    vector<int> sortedSquares(vector<int>& a) {
        int n = a.size(), l = 0, r = n - 1;
        vector<int> out(n);
        for (int w = n - 1; w >= 0; w--) {
            if (abs(a[l]) > abs(a[r])) { out[w] = a[l] * a[l]; l++; }
            else { out[w] = a[r] * a[r]; r--; }
        }
        return out;
    }
};
```
--- quick_theory | Quick theory | mixed
✍️ Two ends hold the extremes of a sorted array — the basis of every opposite-end scan ([[tp-opposite-ends#variations]]).

--- solution | Reference C++ | screenshot
```cpp
class Solution {
public:
    int countPairs(vector<int>& a, int target) {
        sort(a.begin(), a.end());
        int l = 0, r = (int)a.size() - 1, cnt = 0;

            if (a[l] + a[r] < target) { cnt += r - l; l++; }
            else r--;
        }
        return cnt;
    }
};
```

theory_refs:

- pseudocode | Inner skip loops also check l < r | str-palindrome-checks#skipping | The bounds bug in skipping.

stuck_refs:

--- understand | Understand | mixed
✍️ f(string) → true if, after dropping non-alphanumeric characters and ignoring case, it reads the same both ways.
- Length ≤ 2·10⁵, printable ASCII.
- "A man, a plan, a canal: Panama" → true.
--- analyse | Analyse | write
✍️ By hand: compare the first letter with the last, skipping spaces and punctuation, moving inwards.
✍️ Hard part: skipping on both sides without running past each other.
✍️ Edges: empty after cleaning (e.g. " ", ".,") → true; "0P" → false (digits count).
--- brainstorm | Brainstorm: brute → optimal | write
✍️ **1. Simple.** Build a cleaned lowercase copy, compare it with its reverse. O(n) time, O(n) space. Perfectly acceptable as a first answer.
✍️ ↳ The extra string is the only cost; the follow-up asks for O(1) space.
✍️ **2. Optimal.** Two pointers on the original string, skipping non-alphanumerics on each side, comparing lowercase forms. O(n), O(1).
--- algorithm | Algorithm in words | write
✍️ 1. l at the start, r at the end.
✍️ 2. Move l right past non-alphanumeric characters; move r left likewise (never crossing).
✍️ 3. If the lowercase characters differ, return false; else move both inwards.
✍️ 4. If the pointers meet, return true.
--- pseudocode | Pseudocode | write
```
STATE   l = 0; r = n-1
LOOP    while l < r
UPDATE    while l < r and not alnum(s[l]): l++
          while l < r and not alnum(s[r]): r--
CHECK     if lower(s[l]) != lower(s[r]): return false
UPDATE    l++; r--
RETURN  true
```
--- solution | Reference C++ | screenshot
```cpp
class Solution {
public:
    bool isPalindrome(string s) {
        int l = 0, r = (int)s.size() - 1;
        while (l < r) {
            while (l < r && !isalnum(s[l])) l++;
            while (l < r && !isalnum(s[r])) r--;
            if (tolower(s[l]) != tolower(s[r])) return false;
            l++; r--;
        }
        return true;
    }
};
```

|---|---|---|
| r | r | yes |
| a | a | yes |
| c | c | yes |
| e | a | no → false |
--- edges | Edge cases and complexity | mixed
✍️ O(n) time, O(1) space.
✍️ All non-alphanumeric → the inner loops stop at l == r → returns true.
- `tolower` on digits leaves them unchanged.
--- carry | Carry forward | write
✍️ Palindrome / symmetry → opposite ends, compare, move both.
✍️ Any inner skip loop must repeat the outer guard (`l < r`).

+++ sibling: 680 | valid-palindrome-ii | Valid Palindrome II | Easy | must
maps: At the first mismatch you get one deletion: try skipping the left char or the right char.
--- analyse | Analyse | write
✍️ Can the string be a palindrome after deleting at most one character?
✍️ Brute: delete each position and check → O(n²).
--- brainstorm | Brainstorm | write
✍️ Before the first mismatch everything matched, so the deletion must be one of the two mismatching characters. Check s[l+1..r] or s[l..r−1] → O(n).
--- algorithm | Algorithm in words | write
✍️ Walk inwards; on a mismatch return isPal(l+1, r) || isPal(l, r−1); if no mismatch, true.
--- pseudocode | Pseudocode | write
```
while l < r:
    if s[l] != s[r]: return pal(l+1, r) or pal(l, r-1)
    l++; r--
return true
```
--- solution | Reference C++ | screenshot
```cpp
class Solution {
    bool pal(const string& s, int l, int r) {
        while (l < r) if (s[l++] != s[r--]) return false;
        return true;
    }
public:
    bool validPalindrome(string s) {
        int l = 0, r = (int)s.size() - 1;
        while (l < r) {
            if (s[l] != s[r]) return pal(s, l + 1, r) || pal(s, l, r - 1);
            l++; r--;
        }
        return true;
    }
};
```
--- quick_theory | Quick theory | mixed
✍️ "At most one mistake allowed" → handle the first mistake both possible ways, then continue normally ([[str-palindrome-checks#one-deletion]]).

```cpp
CHECK(s.validPalindrome("abc") == false);
CHECK(s.validPalindrome("deeee") == true);
```

=== problem: 3sum
theory_refs:
- brainstorm | Fix one, the rest is sorted two-sum | tp-fix-one-k-sum#think | How O(n³) becomes O(n²).
- pseudocode | Three dedup points | tp-skip-duplicates#idioms | Where to skip and why compare with the previous element.
- solution | `if (a[i] > 0) break` | tp-fix-one-k-sum#template | Early exit on sorted data.
- edges | Compare with a[i−1], not a[i+1] | tp-fix-one-k-sum#pitfalls | The bug that loses [−1, −1, 2].
- understand | Sorting cost | cpp-sort-and-comparators#basics | `std::sort` is O(n log n).
stuck_refs:
- 10 | cx-constraints-to-target#table
- 20 | tp-fix-one-k-sum#idea
- 30 | tp-fix-one-k-sum#template
- 40 | tp-skip-duplicates#idioms
--- understand | Understand | mixed
✍️ f(array) → all **unique** triplets [x, y, z] (values, not indices) with x + y + z = 0.
- n ≤ 3000 → O(n²) = 9·10⁶ is fine, O(n³) = 2.7·10¹⁰ is not.
- [−1, 0, 1, 2, −1, −4] → [[−1, −1, 2], [−1, 0, 1]].
--- analyse | Analyse | write
✍️ Target: O(n²). Values are returned, not indices → sorting is allowed.
✍️ By hand: if I fix −1, I need two numbers summing to +1 — that is Two Sum II on the rest of the array.
✍️ Hard part: **unique** triplets. The input [−1, −1, 2] could produce [−1, −1, 2] twice from different −1s.
✍️ Edges: all zeros [0, 0, 0, 0] → one triplet; fewer than 3 elements; no solution.
--- brainstorm | Brainstorm: brute → optimal | write
✍️ **1. Brute.** Three loops + a set of sorted triplets. O(n³) + dedup overhead.
✍️ ↳ Bottleneck: the inner two loops search for a pair with sum −a[i] — a 2-sum problem.
✍️ **2. Hash per i.** For each i, a hash-set two-sum on the rest. O(n²), but dedup is messy.
✍️ **3. Optimal.** Sort once. For each i: two pointers on i+1..n−1 looking for −a[i]. Dedup by skipping equal values (they are adjacent after sorting). O(n²), O(1) extra.
--- algorithm | Algorithm in words | write
✍️ 1. Sort the array.
✍️ 2. For each index i: skip it if a[i] equals a[i−1] (same first value → same triplets). Stop if a[i] > 0.
✍️ 3. Set l = i+1, r = n−1. While l < r: compute the sum. Too small → l++. Too big → r--.
✍️ 4. On a hit: record it, move both pointers, and skip over equal values on both sides.
--- pseudocode | Pseudocode | write
```
STATE   sort(a); res = []
LOOP    for i in 0..n-3
CHECK     if i > 0 and a[i] == a[i-1]: continue      ← dedup 1
          if a[i] > 0: break
          l = i+1; r = n-1
          while l < r:
              s = a[i] + a[l] + a[r]
              if s < 0: l++
              elif s > 0: r--
              else:
UPDATE            res.add([a[i], a[l], a[r]]); l++; r--
                  while l < r and a[l] == a[l-1]: l++   ← dedup 2
                  while l < r and a[r] == a[r+1]: r--   ← dedup 3
RETURN  res
```
--- solution | Reference C++ | screenshot
```cpp
class Solution {
public:
    vector<vector<int>> threeSum(vector<int>& a) {
        sort(a.begin(), a.end());
        int n = a.size();
        vector<vector<int>> res;
        for (int i = 0; i + 2 < n; i++) {
            if (i > 0 && a[i] == a[i - 1]) continue;
            if (a[i] > 0) break;
            int l = i + 1, r = n - 1;
            while (l < r) {
                int s = a[i] + a[l] + a[r];
                if (s < 0) l++;
                else if (s > 0) r--;
                else {
                    res.push_back({a[i], a[l], a[r]});
                    l++; r--;
                    while (l < r && a[l] == a[l - 1]) l++;
                    while (l < r && a[r] == a[r + 1]) r--;
                }
            }
        }
        return res;
    }
};
```

```cpp
class Solution {
public:
    int threeSumClosest(vector<int>& a, int t) {
        sort(a.begin(), a.end());
        int n = a.size(), best = a[0] + a[1] + a[2];
```

```cpp
class Solution {
public:
    vector<vector<int>> fourSum(vector<int>& a, int target) {
        sort(a.begin(), a.end());
        int n = a.size();
        vector<vector<int>> res;
        for (int i = 0; i < n; i++) {
            if (i > 0 && a[i] == a[i - 1]) continue;
            for (int j = i + 1; j < n; j++) {
                if (j > i + 1 && a[j] == a[j - 1]) continue;
                int l = j + 1, r = n - 1;
                while (l < r) {
                    long long s = (long long)a[i] + a[j] + a[l] + a[r];
                    if (s < target) l++;
                    else if (s > target) r--;
                    else {
                        res.push_back({a[i], a[j], a[l], a[r]});
                        l++; r--;
                        while (l < r && a[l] == a[l - 1]) l++;
                        while (l < r && a[r] == a[r + 1]) r--;
                    }
                }
            }
        }
        return res;
    }
};
```

--- understand | Understand | mixed
✍️ f(heights h) → max over i < j of min(h[i], h[j]) × (j − i).
- n ≤ 10⁵ → O(n²) is too slow.
- [1,8,6,2,5,4,8,3,7] → 49 (walls at index 1 and 8: min(8,7) × 7).
--- analyse | Analyse | write
✍️ This is a DISGUISE: it is not sorted, there is no target — yet it is opposite-end two pointers.
✍️ By hand: start with the widest container (both ends). To find something better I must lose width, so I need more height. The shorter wall caps the height — keeping it can never help.
✍️ Hard part: convincing yourself that discarding the shorter wall loses nothing.
✍️ Edges: n = 2; equal heights; heights of 0.
--- brainstorm | Brainstorm: brute → optimal | write
✍️ **1. Brute.** All pairs. O(n²) → too slow at 10⁵.
✍️ ↳ Bottleneck: checking pairs that obviously cannot win.
✍️ ↳ Unlock: which pairs can be discarded safely? With l and r at the ends and h[l] < h[r], every pair (l, j) with j < r has smaller width and height ≤ h[l]. So l's best is already computed → discard l.
✍️ **2. Optimal.** l = 0, r = n−1. Record area, move the pointer at the **shorter** wall. O(n), O(1).
--- algorithm | Algorithm in words | write
✍️ 1. Pointers at both ends, best = 0.
✍️ 2. Compute the area of the current pair and update best.
✍️ 3. Move the pointer with the smaller height inward (either one if equal).
✍️ 4. Stop when they meet.
--- pseudocode | Pseudocode | write
```
STATE   l = 0; r = n-1; best = 0
LOOP    while l < r
UPDATE    best = max(best, min(h[l], h[r]) * (r - l))
          if h[l] < h[r]: l++  else: r--
RETURN  best
```
--- solution | Reference C++ | screenshot

```cpp
class Solution {
public:
    int maxArea(vector<int>& h) {
        int l = 0, r = (int)h.size() - 1, best = 0;
        while (l < r) {
            best = max(best, min(h[l], h[r]) * (r - l));

        return best;

};
```

=== cs_core: oop-03-inheritance
subject: OOP
title: Inheritance
--- concept | Concept | write
✍️ **Inheritance** lets a class (derived/child) reuse and extend another class (base/parent). It models an **is-a** relationship: a `SavingsAccount` is an `Account`.
✍️ Access in C++: `class D : public B` keeps public as public and protected as protected (the normal choice). `protected`/`private` inheritance hides the base's interface.
✍️ Construction order: base constructor first, then derived. Destruction: derived destructor first, then base.
✍️ Types: single, multiple (`class D : public A, public B`), multilevel (A → B → C), hierarchical (many children of one parent), hybrid.
--- code | C++ example | screenshot
```cpp
class Account {
protected:
    long long balance;
public:
    Account(long long b) : balance(b) {}
    void deposit(long long x) { balance += x; }
};
class Savings : public Account {
    double rate;
public:
    Savings(long long b, double r) : Account(b), rate(r) {}   // call the base constructor
    void addInterest() { balance += (long long)(balance * rate); }   // protected member is visible
};
```
--- interview | Interview questions | mixed
✍️ **Q: What is the diamond problem?** With multiple inheritance, D inherits from B and C which both inherit from A → D gets two copies of A, and calls to A's members are ambiguous. C++ fixes it with **virtual inheritance** (`class B : virtual public A`) so only one A exists. Java avoids it by forbidding multiple class inheritance (interfaces only).
✍️ **Q: Is-a vs has-a?** Inheritance models is-a; **composition** (a member object) models has-a (a Car has an Engine). Prefer composition when the relationship is not truly is-a.
✍️ **Q: What is not inherited?** Constructors (unless `using Base::Base`), destructors, assignment operators and friends.
- **Q: Can a derived class access private members of the base?** No — only protected and public ones.
