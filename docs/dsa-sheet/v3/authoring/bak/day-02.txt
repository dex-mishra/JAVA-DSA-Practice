=== day: 2
micro_title: Hashing — remember what you have seen
micro_theory: hash-table-internals, cpp-unordered-map-set, hash-complement-lookup, hash-frequency-counting, cpp-container-choice
--- micro | Micro-theory (10 minutes) | mixed
Yesterday you kept a few variables about the past. Today you keep **everything** about the past — in a hash map — so any question "have I seen X?" costs O(1).

✍️ A hash table computes where a key lives instead of searching for it, so insert and lookup are O(1) on average ([[hash-table-internals#picture]]).
✍️ `unordered_map<key, value>`: `mp[k]++` to count, `mp.count(k)` / `mp.find(k)` to ask. **`mp[k]` inserts a missing key** — never use it just to ask ([[cpp-unordered-map-set#bracket-trap]]).
✍️ Small dense keys (letters) → a plain array `int cnt[26]` beats any map ([[cpp-container-choice#rule]]).

Two patterns today:
- **Complement lookup** — for each x, ask whether its partner (target − x) has already appeared ([[hash-complement-lookup#idea]]).
- **Frequency counting** — count once, answer every "how many" in O(1) ([[hash-frequency-counting#idea]]).
--- card | Pattern card | write
✍️ COMPLEMENT LOOKUP — trigger: "pair that sums/differs to …", unsorted. need = target − x; check map; THEN insert x.
✍️ FREQUENCY COUNT — trigger: "anagram, same characters, appears more than, most frequent, duplicate". One table, ++ for one input, −− for the other.
✍️ START OF RUN — trigger: "longest consecutive", O(n), unsorted. Only walk from v where v−1 is missing.

=== problem: two-sum
theory_refs:

--- understand | Understand | mixed
✍️ f(unsorted array a, target) → indices [i, j], i ≠ j, with a[i] + a[j] = target. Exactly one answer exists.
- n ≤ 10⁴ (so O(n²) actually passes — but the follow-up asks for better than O(n²), and interviews always do).
- Values up to ±10⁹.
--- analyse | Analyse | write
✍️ Target complexity: O(n) or O(n log n).
✍️ By hand on [2, 7, 11, 15], target 9: at 2 I think "I need a 7" and my eyes scan for 7. That scan is the expensive part.
✍️ Hard part: finding the partner without scanning, while still returning **original indices** (so sorting is awkward).
✍️ Edges: [3, 3] target 6 (equal values); [3, 2, 4] target 6 (3 must not pair with itself).
--- brainstorm | Brainstorm: brute → optimal | write
✍️ **1. Brute.** All pairs i < j. O(n²) time, O(1) space.
✍️ ↳ Bottleneck: the inner loop. Its job: "search the array for the value target − a[i]".
✍️ ↳ Unlock: "Am I searching for something I could have remembered?" — yes, a specific known value.
✍️ **2. Better (sort + two pointers).** O(n log n), but sorting loses the original indices; you must sort (value, index) pairs. Workable, more code.
✍️ **3. Better (two-pass hash).** Put every value → index in a map, then look up target − a[i] for each i, making sure the index found is not i. O(n).
✍️ **4. Optimal (one-pass hash).** Look up first, insert after. Only earlier elements are in the map → no self-pairing check needed, and you stop at the first hit. O(n) time, O(n) space.
--- algorithm | Algorithm in words | write
✍️ 1. Create an empty map from value to index.
✍️ 2. Walk the array. For element x at index i, compute need = target − x.
✍️ 3. If need is in the map, return [map[need], i].
✍️ 4. Otherwise store x → i and continue.
--- pseudocode | Pseudocode | write
```
STATE   seen = map value → index (empty)
LOOP    for i in 0..n-1, x = a[i]
CHECK     need = target - x
          if need in seen: return [seen[need], i]
UPDATE    seen[x] = i                  ← after the check
RETURN  []                             (unreachable: an answer is guaranteed)
```
--- solution | Reference C++ | screenshot
```cpp
class Solution {
public:
    vector<int> twoSum(vector<int>& a, int target) {
        unordered_map<int, int> seen;            // value -> index
        for (int i = 0; i < (int)a.size(); i++) {
            int need = target - a[i];
            auto it = seen.find(need);
            if (it != seen.end()) return {it->second, i};
            seen[a[i]] = i;
        }
        return {};
    }
};
```
--- dry_run | Dry run | screenshot
Input [3, 2, 4], target 6:
| i | x | need | in seen? | seen after |
|---|---|---|---|---|
| start | | | | {} |
| 0 | 3 | 3 | no (3 is not inserted yet) | {3:0} |
| 1 | 2 | 4 | no | {3:0, 2:1} |
| 2 | 4 | 2 | yes → return [1, 2] | |
If we had inserted before checking, i = 0 would have found 3 and returned [0, 0].
--- edges | Edge cases and complexity | mixed
✍️ O(n) average time, O(n) space. Brute force is the classic O(n²) time / O(1) space trade-off.
✍️ Duplicates [3, 3]: at i = 1, need 3 is already in the map from i = 0 → [0, 1]. Correct because we check before inserting.
- Overflow check: values and target are within ±10⁹, so `target − a[i]` is within ±2·10⁹ — just inside int's limit of ≈ 2.147·10⁹. Fine here, but in variants with larger values use `long long need` ([[cpp-integer-overflow#ranges]]).
--- carry | Carry forward | write
✍️ Pair search on **unsorted** data → store what you have seen, look up what you need.
✍️ Always **check, then insert** when an element must not pair with itself.
✍️ The map's value is whatever the question asks for: index here, count when counting pairs, last index when distance matters.
--- followups | Interview follow-ups | screenshot
- *The array is sorted; O(1) space?* Two pointers from both ends (tomorrow, [[tp-opposite-ends]]).
- *Return all pairs / count pairs.* Store counts; add count[need] at each step.
- *Three numbers summing to target?* Sort + fix one + two pointers (tomorrow's 3Sum).
- *What if the input does not fit in memory?* Sort externally and two-pointer, or hash-partition the data into chunks by value.
--- tests | Tests | hidden

vector<int> b = {3, 2, 4};
CHECK((s.twoSum(b, 6) == vector<int>{1, 2}));

--- analyse | Analyse | write
✍️ Return true if any value appears at least twice.
✍️ Brute: all pairs O(n²). Sort and compare neighbours: O(n log n), O(1) extra.
--- brainstorm | Brainstorm | write
✍️ The question at each element is "have I seen this exact value?" → hash set. Check, then insert. O(n) time, O(n) space.
--- algorithm | Algorithm in words | write
✍️ Walk the array; if the value is already in the set, return true; otherwise insert it. Return false at the end.
--- pseudocode | Pseudocode | write
```
seen = empty set
for x in a:
    if x in seen: return true
    seen.insert(x)
return false
```
--- solution | Reference C++ | screenshot
```cpp
class Solution {
public:
    bool containsDuplicate(vector<int>& a) {
        unordered_set<int> seen;
        for (int x : a) {
            if (seen.count(x)) return true;
            seen.insert(x);
        }
        return false;
    }
};
```
--- quick_theory | Quick theory | mixed
✍️ Set = map without values; use it when you only need membership ([[cpp-unordered-map-set#api]]).
- Trade-off talk: sorting gives O(1) extra space at O(n log n) time.

+++ sibling: 219 | contains-duplicate-ii | Contains Duplicate II | Easy | optional
maps: Store the last index of each value; a duplicate counts only if it is within distance k.
--- analyse | Analyse | write
✍️ True if some value appears at indices i ≠ j with |i − j| ≤ k.
--- brainstorm | Brainstorm | write
✍️ For each x, the best earlier partner is its **most recent** occurrence (closest). Map value → last index. O(n). (Window alternative: a set of the last k elements.)
--- algorithm | Algorithm in words | write
✍️ For each i: if x was seen and i − last[x] ≤ k → true. Update last[x] = i.
--- pseudocode | Pseudocode | write
```
last = map
for i, x in a:
    if x in last and i - last[x] <= k: return true
    last[x] = i
return false
```
--- solution | Reference C++ | screenshot
```cpp
class Solution {
public:
    bool containsNearbyDuplicate(vector<int>& a, int k) {
        unordered_map<int, int> last;
        for (int i = 0; i < (int)a.size(); i++) {
            auto it = last.find(a[i]);
            if (it != last.end() && i - it->second <= k) return true;
            last[a[i]] = i;
        }
        return false;
    }
};
```
--- quick_theory | Quick theory | mixed
✍️ The map value is chosen by what the check needs: here the **latest** index.

=== problem: valid-anagram
theory_refs:
- brainstorm | Sort-and-compare vs counting | hash-frequency-counting#think | Why counting removes the sort.
- pseudocode | One table: ++ for s, −− for t | hash-frequency-counting#template | The cancel-out trick.
- solution | `int cnt[26]` instead of a map | cpp-container-choice#anagram-example | Why an array is the right container for lowercase letters.
- edges | Length check first | hash-frequency-counting#pitfalls | Different lengths can never be anagrams.
stuck_refs:
- 10 | cpp-string#basics
- 20 | hash-frequency-counting#idea
- 30 | hash-frequency-counting#template
--- understand | Understand | mixed
✍️ f(s, t) → true if t is a rearrangement of s (same letters, same counts).
- Lowercase English letters, length ≤ 5·10⁴.
- "anagram", "nagaram" → true; "rat", "car" → false.
--- analyse | Analyse | write
✍️ Order does not matter; only how many of each letter. That is a frequency question.
✍️ Hard part: none conceptually — the decision is which container to use.
✍️ Edges: different lengths → false immediately; one character.
--- brainstorm | Brainstorm: brute → optimal | write
✍️ **1. Brute.** For each character of s, find and remove one copy from t. O(n²).
✍️ ↳ Bottleneck: searching t for each character.
✍️ **2. Better.** Sort both strings and compare. O(n log n).
✍️ ↳ Bottleneck: sorting establishes a full order, but we only need equal counts.
✍️ **3. Optimal.** Count letters: +1 for s, −1 for t; all 26 must end at 0. O(n) time, O(1) space (26 is a constant).
--- algorithm | Algorithm in words | write
✍️ 1. If the lengths differ, return false.
✍️ 2. Make an array of 26 zeros.
✍️ 3. For each position, add 1 for s's letter and subtract 1 for t's letter.
✍️ 4. Return true iff every entry is 0.
--- pseudocode | Pseudocode | write
```
STATE   if len(s) != len(t): return false
        cnt[26] = 0
LOOP    for i in 0..n-1
UPDATE    cnt[s[i]-'a']++ ; cnt[t[i]-'a']--
CHECK   for k in 0..25: if cnt[k] != 0: return false
RETURN  true
```
--- solution | Reference C++ | screenshot
```cpp
class Solution {
public:
    bool isAnagram(string s, string t) {
        if (s.size() != t.size()) return false;
        int cnt[26] = {0};
        for (int i = 0; i < (int)s.size(); i++) {
            cnt[s[i] - 'a']++;
            cnt[t[i] - 'a']--;
        }
        for (int k = 0; k < 26; k++) if (cnt[k] != 0) return false;
        return true;
    }
};
```
--- dry_run | Dry run | screenshot
s = "rat", t = "car":
| i | s[i] | t[i] | changed counts |
|---|---|---|---|
| 0 | r | c | r:+1, c:−1 |
| 1 | a | a | a: 0 |
| 2 | t | r | t:+1, r:0 |
Final non-zeros: c = −1, t = +1 → false.
--- edges | Edge cases and complexity | mixed
✍️ O(n) time, O(1) space (fixed 26 counters).
- Unicode follow-up: the alphabet is no longer small → `unordered_map<char32_t,int>` or a map over code points.
--- carry | Carry forward | write
✍️ "Same multiset of items" → count, don't sort.
✍️ Two inputs to compare → one table with + and −; check all zero.
✍️ Letters only → `int cnt[26]` with `c − 'a'`.
--- followups | Interview follow-ups | screenshot
- *What if inputs contain Unicode?* Hash map keyed by character.
- *Group many words into anagram groups.* The sorted word (or count signature) becomes a key ([[hash-derived-keys]]).
- *Find all anagrams of p inside s.* Fixed window of counts (Day 8, [[str-anagram-window]]).

+++ sibling: 49 | group-anagrams | Group Anagrams | Medium | must
maps: Instead of comparing two words, compute each word's canonical key and group words with equal keys.
--- analyse | Analyse | write
✍️ Group the words that are anagrams of each other; any order.
✍️ Brute: compare every pair with Valid Anagram → O(n² · L).
--- brainstorm | Brainstorm | write
✍️ Bottleneck: pairwise comparison. Fix: two words are anagrams iff their sorted forms are equal → use the sorted form as a hash-map key → O(n · L log L).
✍️ (Count signature key gives O(n · L).)
--- algorithm | Algorithm in words | write
✍️ For each word, sort a copy to get its key; append the word to groups[key]. Output all groups.
--- pseudocode | Pseudocode | write
```
groups = map key → list
for w in words: key = sorted(w); groups[key].append(w)
return all lists in groups
```
--- solution | Reference C++ | screenshot
```cpp
class Solution {
public:
    vector<vector<string>> groupAnagrams(vector<string>& words) {
        unordered_map<string, vector<string>> groups;
        for (auto& w : words) {
            string key = w;
            sort(key.begin(), key.end());
            groups[key].push_back(w);
        }
        vector<vector<string>> out;
        for (auto& [k, g] : groups) out.push_back(g);
        return out;
    }
};
```

✍️ "Group items that are equivalent" → canonical key + map of lists ([[hash-derived-keys#idea]]).
✍️ Key choice trade-off: sorted string vs count signature ([[hash-derived-keys#key-choice]]).

=== problem: majority-element
theory_refs:
- brainstorm | Map → sort → voting | hash-boyer-moore-voting#think | The three levels and what each costs.
- brainstorm | O(1) space is the hint | hash-boyer-moore-voting#recognise | A banned data structure names the technique.
- pseudocode | Adopt before comparing | hash-boyer-moore-voting#pitfalls | The order of the two lines in the loop.
- edges | Why the survivor is the majority | hash-boyer-moore-voting#why-it-works | The cancellation argument for interviews.
stuck_refs:
- 10 | hash-frequency-counting#template
- 20 | hash-boyer-moore-voting#idea
- 30 | hash-boyer-moore-voting#template
- 40 | hash-boyer-moore-voting#why-it-works
--- understand | Understand | mixed
✍️ f(array) → the value that appears more than ⌊n/2⌋ times (guaranteed to exist).
- n ≤ 5·10⁴. Follow-up: O(n) time and O(1) space.
--- analyse | Analyse | write
✍️ First solve it with what you know today (a frequency map). Then the follow-up removes the map — that is the TWIST.
✍️ By hand on [2,2,1,1,1,2,2]: imagine pairing each 1 with a 2 and throwing both away. 2s are left over. The majority always survives this.
✍️ Edges: n = 1; majority at the very end.
--- brainstorm | Brainstorm: brute → optimal | write
✍️ **1. Brute.** For each value count it with a scan. O(n²).
✍️ **2. Better (frequency map).** Count all, return the one with count > n/2. O(n) time, O(n) space.
✍️ **3. Better (sort).** The majority must cover the middle index → return a[n/2]. O(n log n), O(1).
✍️ ↳ Bottleneck for O(1) space: storing a count for **every** value, when only one value matters.
✍️ ↳ Unlock: "a forbidden data structure is a hint" — no map means a counting/cancelling argument.
✍️ **4. Optimal (Boyer–Moore).** One candidate + one counter; equal → +1, different → −1, counter 0 → adopt the new value. O(n), O(1).
--- algorithm | Algorithm in words | write
✍️ 1. Start with no candidate and count 0.
✍️ 2. For each value: if the count is 0, make this value the candidate.
✍️ 3. If the value equals the candidate, increase the count; otherwise decrease it.
✍️ 4. The candidate at the end is the majority.
--- pseudocode | Pseudocode | write
```
STATE   cand = none; cnt = 0
LOOP    for x in a
UPDATE    if cnt == 0: cand = x          (adopt FIRST)
          cnt += (x == cand) ? +1 : -1
RETURN  cand
```
--- solution | Reference C++ | screenshot
```cpp
class Solution {
public:
    int majorityElement(vector<int>& a) {
        int cand = 0, cnt = 0;
        for (int x : a) {
            if (cnt == 0) cand = x;
            cnt += (x == cand) ? 1 : -1;
        }
        return cand;
    }
};
```

--- edges | Edge cases and complexity | mixed
✍️ O(n) time, O(1) space.
✍️ The result is guaranteed only because a majority is guaranteed. Without the guarantee, verify with a second counting pass.
--- carry | Carry forward | write
✍️ Always solve it the "known" way first (frequency map), then remove the expensive part.
✍️ "O(1) extra space" on a counting problem → think cancellation (Boyer–Moore), XOR, or arithmetic — never a smarter map.
✍️ Majority > n/k → at most k−1 candidates.
--- followups | Interview follow-ups | screenshot

maps: More than n/3 → at most two survivors; keep two candidates and two counters, then verify.
--- analyse | Analyse | write
✍️ Return all values appearing more than ⌊n/3⌋ times; O(1) space follow-up.
✍️ At most two such values can exist (three would need more than n elements).
--- brainstorm | Brainstorm | write
✍️ Map → O(n) space. Voting with two candidates: a value different from **both** cancels one copy of each. Survivors are only candidates → count them again to verify.
--- algorithm | Algorithm in words | write
✍️ 1. Pass 1: if x matches a candidate, increment its count; else if a count is 0, adopt x there; else decrement both. 2. Pass 2: count both candidates; keep those > n/3.
--- pseudocode | Pseudocode | write
```
c1, c2 = none; n1 = n2 = 0
for x in a:
    if x == c1: n1++
    elif x == c2: n2++
    elif n1 == 0: c1 = x; n1 = 1
    elif n2 == 0: c2 = x; n2 = 1
    else: n1--; n2--

```
--- solution | Reference C++ | screenshot
```cpp
class Solution {
public:
    vector<int> majorityElement(vector<int>& a) {
        int c1 = 0, c2 = 1, n1 = 0, n2 = 0;          // different initial candidates
        for (int x : a) {
            if (x == c1) n1++;
            else if (x == c2) n2++;
            else if (n1 == 0) { c1 = x; n1 = 1; }
            else if (n2 == 0) { c2 = x; n2 = 1; }
            else { n1--; n2--; }
        }
        n1 = n2 = 0;
        for (int x : a) { if (x == c1) n1++; else if (x == c2) n2++; }
        vector<int> out;
        int n = a.size();
        if (n1 > n / 3) out.push_back(c1);
        if (n2 > n / 3) out.push_back(c2);
        return out;
    }
};
```

=== problem: longest-consecutive-sequence
theory_refs:
- understand | "O(n)" on unsorted input | hash-set-runs#recognise | The constraint that rules out sorting.
- brainstorm | Re-walking each run from every element | hash-set-runs#think | Why the naive set version is O(n²).
- pseudocode | `if v−1 in set: continue` | hash-set-runs#idea | The start-of-run rule.
- solution | Iterate the set, not the array | hash-set-runs#pitfalls | Duplicates would re-walk runs.
- edges | Why the nested loop is O(n) | cx-amortised-analysis#counting-trick | Charge each value to one walk.
stuck_refs:
- 10 | cx-constraints-to-target#table
- 20 | hash-set-runs#idea
- 30 | hash-set-runs#template
- 40 | hash-set-runs#pitfalls
--- understand | Understand | mixed
✍️ f(unsorted array) → length of the longest set of values that form consecutive integers v, v+1, …, v+L−1 (positions do not matter).
- n ≤ 10⁵, must be O(n).
- [100, 4, 200, 1, 3, 2] → 4 (1, 2, 3, 4).
--- analyse | Analyse | write
✍️ This is a DISGUISE: nothing says "hash set", but the O(n) requirement on unsorted data does.
✍️ By hand: I look at 4 and ask "is 5 there? is 3 there?". If I always start counting from the smallest number of a run, I count each run once.
✍️ Hard part: avoiding counting the same run many times.
✍️ Edges: empty array → 0; duplicates [1, 2, 0, 1] → 3; negatives.
--- brainstorm | Brainstorm: brute → optimal | write
✍️ **1. Brute.** For each value v, check v+1, v+2, … by scanning the array each time. O(n³) worst.
✍️ **2. Better.** Sort, then scan counting runs and skipping duplicates. O(n log n) — fails the O(n) requirement.
✍️ **3. Better.** Put values in a set; for each value walk upward with O(1) lookups. O(n²) on input like 1..n (each run walked from every element).
✍️ ↳ Bottleneck: a run of length L is walked L times.
✍️ ↳ Unlock: every run has exactly one start — the value whose predecessor is missing. Walk only from starts.
✍️ **4. Optimal.** Set + start-of-run. Each value is part of exactly one walk → O(n).
--- algorithm | Algorithm in words | write
✍️ 1. Insert all values into a hash set.
✍️ 2. For each value v in the set: if v − 1 is also in the set, skip it (not a start).
✍️ 3. Otherwise walk v+1, v+2, … while present, counting the length.
✍️ 4. Keep the maximum length.
--- pseudocode | Pseudocode | write
```
STATE   s = set(a); best = 0
LOOP    for v in s                       (the set, so duplicates are gone)
CHECK     if (v - 1) in s: continue      (not the start of a run)
UPDATE    len = 1
          while (v + len) in s: len++
          best = max(best, len)
RETURN  best
```
--- solution | Reference C++ | screenshot
```cpp
class Solution {
public:
    int longestConsecutive(vector<int>& a) {
        unordered_set<int> s(a.begin(), a.end());
        int best = 0;
        for (int v : s) {
            if (s.count(v - 1)) continue;
            int len = 1;
            while (s.count(v + len)) len++;
            best = max(best, len);
        }
        return best;
    }
};
```

✍️ O(n) average time: n inserts; each value is checked once as a possible start and visited at most once by a walk. O(n) space.

--- carry | Carry forward | write

✍️ A loop inside a loop can still be O(n) if each element is charged to one inner walk.

=== cs_core: oop-02-encapsulation
subject: OOP
title: Encapsulation and access specifiers
--- concept | Concept | write
✍️ **Encapsulation** = bundling data with the functions that operate on it, and **hiding** the data so it can only be changed through those functions.
✍️ Why: the class can enforce its own rules (an account balance never goes negative), and the internal representation can change without breaking code that uses the class.
✍️ C++ access specifiers: `private` (only the class itself and friends), `protected` (also derived classes), `public` (everyone).
✍️ Getters/setters expose controlled access; a setter can validate before changing state.
--- code | C++ example | screenshot
```cpp
class Account {
private:
    long long balance = 0;               // hidden state
public:
    bool withdraw(long long amt) {       // the only way to reduce balance
        if (amt <= 0 || amt > balance) return false;   // rule enforced in one place
        balance -= amt;
        return true;
    }
    void deposit(long long amt) { if (amt > 0) balance += amt; }
    long long getBalance() const { return balance; }
};
```
- `friend` functions/classes can access private members; use sparingly (it weakens encapsulation).
--- interview | Interview questions | mixed
✍️ **Q: Encapsulation vs abstraction?** Encapsulation hides *data* behind an interface (how the class protects its state). Abstraction hides *complexity* — exposing what an object does, not how (Day 5).
✍️ **Q: Difference between private and protected?** Protected members are also accessible inside derived classes; private ones are not.
✍️ **Q: Is a class with public data members encapsulated?** No — anyone can put the object into an invalid state.
- **Q: What is data hiding?** The mechanism (private members) that achieves encapsulation.
- **Q: Default access in class vs struct?** class → private, struct → public.
